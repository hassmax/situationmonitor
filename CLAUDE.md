# Global Situation Monitor: notes for Claude Code

A self-updating 3D globe of armed-conflict events, built from public OSINT posts and news feeds, running entirely on free services. The owner is a law student focused on national security, not a developer: explain changes in plain language in PR descriptions, and keep the tool simple, fast, and honest about uncertainty.

## How it runs

- `.github/workflows/update.yml` runs every 15 minutes. GitHub delays and drops scheduled runs (on 2026-10-03 one ran between 10:26 and 14:10 UTC), so `.github/workflows/heartbeat.yml` keeps a job running that starts an update (workflow_dispatch, which GitHub doesn't drop) whenever the last one began 14+ minutes ago, and starts its own next run before the 6-hour job limit (a 3-hourly schedule restarts the chain if it breaks; cancelling a heartbeat by hand stops the chain until then, disabling the workflow stops it for good). update.yml keeps its own schedule as a backup, at :04, :19, :34 and :49 (the top of the hour is the worst) (plus on pushes to `main` that touch `site/`, `pipeline/`, or the workflow, and manually with an optional `lookback_days` backfill input).
- It restores the whole orphan `data` branch (`state.json`, `events.json`, `archive/`), stopping if the branch exists but cannot be fetched (saving without it would wipe the archive), runs `pipeline/run.py`, force-pushes everything back to `data` as one commit, copies `site/` plus the generated `out/events.json` and `out/reports/` into `_site/`, stamps `__BUILD__` in `index.html` with the commit SHA (cache-busting: `app.js?v=<commit>`; the step was missing until 2026-10-04, so browsers could run a cached app.js against newer data, which left every event without reports after the data split), and deploys to GitHub Pages. events.json carries the same commit as `build`; an open page whose own version (`OWN_BUILD`, from its script address) differs reloads (`checkBuild`: at once if hidden or untouched for 2 minutes, else a "The site was updated. Reload" note, and again when it next goes idle; once per version per tab, `sessionStorage` `gsm_reload`, to a `?v=<build>` address past any cached copy, cleaned from the address after).
- Secrets: `GEMINI_API_KEY` (free Gemini API, OpenAI-compatible endpoint), `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` (Telegram via Telethon). Optional variable `NOMINATIM_EMAIL`. Optional secret `FIRMS_MAP_KEY` (NASA FIRMS, free with an email address: the heat agent, below; without it the agent does nothing). Optional secrets `CEREBRAS_API_KEY`, `OPENROUTER_API_KEY` (free outside providers for the regional analyst, `providers.py`; without them Gemini writes it). Optional Telegram alerts: secrets `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, variable `DASHBOARD_URL`. Never print, log, or commit secret values.
- Free-tier limits matter: Gemini Flash-Lite allows roughly 500 requests/day (the pipeline budgets 470, `daily_llm_calls`, batching up to 40 posts per request, `batch_max_items`, since 2026-10-02 (was 25): the ~4,700-token instructions go with every call; raised from 400 on 2026-09-30); news headlines the model judged irrelevant are remembered for a day and not sent again (`extract.skip_rejected`, `state["rejected_heads"]`); Actions minutes are free because the repo is public. All model use shares one daily counter (`extract.calls_remaining`); calls answered with HTTP 5xx (overloaded or down) or that never reach the provider are not counted (`extract.Busy`), so an outage can't drain the budget, nor are one-off calls refused with 429 (rate limit); HTTP 402 ("prepayment credits are depleted", seen 2026-10-04) is not counted either (`extract.OutOfCredit`): posts keep their place in the queue (no `attempts`), the model is left alone for `CREDIT_RECHECK` (1 h, `state["llm_out_of_credit"]`), then one probe, instead of every model being probed every run; replies are parsed leniently (`extract._repairs`: line breaks in strings, trailing commas, Python None/True/False, botched \u codes), and an unreadable one-off reply is logged with where it breaks (`json_error`); when the chosen model is busy, a run switches once to another model, from `llm_models` (Flash-Lite) and then `llm_fallback_models` (regular Flash, also free, separate smaller limit), and a backup is dropped for the preferred models after `FALLBACK_RECHECK` (1 h): extraction keeps a reserve of `extraction_reserve` (30) calls, the regional analyst stops using Gemini below `brief_min_calls` (5), and the same-story check below `dedupe_min_calls` (10). Every call is also tallied by purpose (`state["llm_calls"]["by"]`: extract, dedupe, recency, analysis (was brief), split, fleet, maproom, frontline, frontline_review, frontline_isw, frontline_social, frontline_imagery, frontline_news, probe; `ask_json(..., purpose=)`), and the checks that run after extraction have paced daily shares (`extract.SHARES`, `share_left`: `dedupe_daily_max` 140 (was 90 until 2026-10-02, when it ran out daily with 100 groups waiting and only 281 of 470 calls used), `recency_daily_max` 48, spread over the UTC day plus `SHARE_BURST` 4; `maproom_daily_max` 16, not spread (`UNPACED`): ISW's maps come out together around 01:00 UTC; `frontline_daily_max` 40 and `frontline_review_daily_max` 60 (24 until 2026-10-04, raised for the first pass of town searches), paced; `frontline_isw_daily_max` 60, not paced, so ISW's two-week backlog is read up front; `analysis_daily_max` 24, paced; `frontline_social_daily_max` 40, `frontline_imagery_daily_max` 8 and `frontline_news_daily_max` 24, paced): on 2026-09-30 the same-story check took most of the then 400 and extraction stopped with 358 posts waiting. New features must not add model calls without budgeting them here (a purpose, and a share if they can run every 15 minutes).

## Layout

- `pipeline/run.py`: orchestrator. Fetch → keyword prefilter → model extraction (batched, budgeted, queued) → geocode (OSM Nominatim, cached) → merge → confidence scoring → write `events.json` and the reports files (`pipeline/publish.py`: the reports behind each event, four fifths of the data (7 MB of 8.7 on 2026-10-04), go into `REPORT_BUCKETS` (64) files `reports/NN.json` by a hash of the event id that `bucketOf` in app.js computes the same way; `events.json` keeps each event's distinct source names as `src`, for search; all 64 files are written every run). The page fetches a reports file when an event is opened (`reportsFor`, `fillReports`), or when it is pointed at (`prefetchReports`); demo data keeps its reports inline.
- `pipeline/sources/`: `bluesky.py` (public API, no login; plus `search`, the patrol: Bluesky's keyword search on api.bsky.app (the public AppView refuses searches with 403), `bluesky_search` in sources.yaml: queries naming aircraft with their type ("B-52 bombers": "B-52" alone found the band, "bombers" Catalan firefighters) and forward bases, English posts (`lang`), from the last `SEARCH_HOURS` (6) by listed accounts (credited as themselves) or accounts with `min_followers` (2,000; `getProfiles`), keyword-filtered; unlisted authors share group `bluesky-search`, in `merge.WEAK_GROUPS` with `google-news`: counted only when no listed source reported the event, and weak groups together count once; added 2026-10-04 after OSINTtechnical's B-1 departures from RAF Fairford were missed: X can't be read free (paid API; xcancel 451, nitter down), OSINTtechnical's Telegram stopped in 2022 and its Bluesky in February 2026), `telegram.py`, `rss.py` (incl. Google News searches), `gdelt.py` (used only to corroborate, not drawn), `maproom.py` (ISW's maps, below). The owner's list of leading national outlets (NYT, Xinhua, Der Spiegel, NHK, BBC, Indian Express, Le Monde, TASS, Corriere della Sera, CBC, Grupo Globo, El País, Yonhap, Reforma, ABC Australia, Anadolu, Kompas, NRC, Al Arabiya, NZZ) is read through Google News `site:` searches (`gnews-majors-*`, `gnews-state-wires`, and one per language: `gnews-de/it/nl/es/pt/id`, each in that language's Google News edition with its own keywords, which the prefilter also knows: `_EUROPE_ASIA`, prefilter version 4); all are listed outlets. North Korea and the Korean Peninsula: `gnews-korea` (the Indo-Pacific search needs PLA, coast guard or US Navy in the story). Front-line ground reporting (2026-10-04, the owner asked to map like ISW and Black Bird Group, whose maps rest on geolocated footage, both sides' statements, satellite imagery and field networks): regional newsrooms that report towns changing hands, checked from GitHub's servers that day: Sudan War Monitor (`kind: analysis`), Sudans Post, Dabanga, Myanmar Now, DVB, BNI, Somali Guardian, Radio Okapi, Actualite.cd, RFI Afrique, all unaligned, and lefaso.net, `side: BF` (works under Burkina Faso's junta and relays the army; listed under the Sahel `STATE` actor's sources); capture headlines ("Captures Mazroub", "take control of", "retook") and French war words are in the keyword filter as prefilter version 6 (`_CAPTURE`, `_FRENCH`). Irrawaddy, Mizzima, Addis Standard, Garowe Online and the Defense Post refuse GitHub's servers. Listed under `outlets:` too (2026-10-05), so their Google News results count on their own rather than in the shared `google-news` group (groups match their feeds): Sudans Post, Dabanga, Sudan War Monitor, Myanmar Now, DVB, BNI, The Irrawaddy, Mizzima, Somali Guardian, Radio Okapi, Actualite.cd, RFI, Africanews (group `euronews` with Euronews), The Africa Report and Jeune Afrique (one group), Ethiopia Observer, Agenzia Nova; ACP (Congolese state, side CD) and KT Press, Taarifa and The New Times (Rwandan pro-government, side RW: Rwanda backs M23); Ethiopia's ENDF actor now lists side ET, so Fana speaks for it. Force movements (2026-10-04): Telegram aggregators OSINTdefender, ClashReport and CIG_telegram (one shared group `osint-aggregators`: they repost one another and the same X accounts), Itamilradar (military flight tracking), manniefabian (The Times of Israel's military correspondent, group `timesofisrael`); RSS from The War Zone, UK Defence Journal, The Aviationist, Air & Space Forces Magazine (also listed outlets, with Breaking Defense, Military Times, Forces News); `gnews-airpower` (bombers, fighters, tankers deploying, arriving, departing, headed home) and `gnews-airbases` (Fairford, Lakenheath, Mildenhall, Diego Garcia, Al Udeid, Prince Sultan, Muwaffaq Salti, Incirlik, Akrotiri, Souda Bay, Andersen, Kadena); aircraft types and base words in the keyword filter as prefilter version 7 (`_AIR`). Yemen both ways: Telegram `Alomhoar` (Al-Mehwar News, partisan, side YE, keyword-filtered, Arabic attack words added in prefilter version 5) and `gnews-yemen-coalition` (Arabic search of SPA, Al Arabiya, Al Hadath, Asharq Al-Awsat, all side SA).
- `pipeline/extract.py`: the model prompt (`SYSTEM_PROMPT`), event types, keyword prefilter (`CONFLICT_RE`), model probing and batching. Diplomacy also covers formal changes in international commitments and relations anywhere (leaving, suspending or joining a treaty, alliance or international body; expulsions, recalled ambassadors, cut relations; new sanctions packages against a state, not designations of individuals unless tied to a conflict), in the `global` theater ("Worldwide", no countries, set only by the model, `listed: false`: no row in the theater list, always shown, filtered only by "Diplomacy, legal") when no conflict theater fits, placed at the acting state's capital; searched by `gnews-commitments`; parties may be a body's short name up to 8 letters (GRECO). The type is what happened, not the vehicle: an attack aboard a civilian airliner is hybrid (state blamed or suspected) or not relevant, never airstrike or naval; consequences of an incident (flights suspended, repatriation flights, investigations, "updates") are not events. When words are added to the prefilter, add them as a new `_ADDED_WORDS` version: seen posts only the new words let through get one more look (`state["prefilter_version"]`).
- `pipeline/geo.py`: geocoding, theater assignment, named-sea fallback coordinates. When the model's coordinates and the lookup disagree by 300+ km, the model's stay (approximate) unless a reverse lookup (`country_at`) shows them outside the country it named; then the lookup wins. `repair` re-checks stored approximate pins, `REPAIR_PER_RUN` per run, once per `REPAIR_VERSION`. Region names ("Middle East", "Europe", "Sahel"; `REGIONS`) are never looked up (Nominatim put "Middle East" in Baltimore): they go to a labeled anchor, approximate, for new and stored events (`pin_commands`). For strikes, fighting and naval incidents (`IN_THEATER_TYPES`), a lookup more than `THEATER_KM` (5,000 km) from the theater's camera point is not used (the model's estimate, if in range, is); a theater's `reach_km` overrides it (Indo-Pacific 6,500: Karachi and the Arabian Sea are 5,200-5,500 km from its camera). The model's own coordinates get the same check even when the lookup finds nothing (a sea searched inside the named country finds nothing: "Caribbean Sea" came back as 15, 75, southern India). A place that is just a sea or strait's name (`sea_exact`: "Sea of Japan", "the Red Sea") is never looked up (a lookup limited to the named country found a Sea of Japan in Kawasaki and the Taiwan Strait in Kaohsiung); it goes to the `SEAS` anchor, approximate, for new events, stored events and attack-wave targets (`pin_commands`). An event whose place names a sea in `SEAS` is pinned within `SEA_KM` (2,000) of it, else at its anchor (`_off_sea`; stored events too, in `pin_commands`). The "far outside" log line is written once per place and run.
- `pipeline/sources/maproom.py`: ISW's Map Room (understandingwar.org/analysis/map-room), the owner's priority source, checked hourly (`CHECK_EVERY`) through the site's WordPress API (`/wp-json/wp/v2/map`, browser user agent; reachable from Actions, not from the Claude sandbox). Maps are images with a title and no caption, so each new map is read by the model (`ask_json(..., images=)`, purpose `maproom`, at most `PER_RUN` 3 a run and `maproom_daily_max` a day): it lists text boxes and legend-dated symbols on printed place names ("significant fighting in the past 24 hours" near Hayfan), with the province or oblast, keeping ISW's attribution; for "Assessed Control of Terrain" maps the previous edition of the same series (`series`, within `PREVIOUS_MAX`) is sent too, for front-line changes. Findings become items (`SOURCE`: "ISW Map Room", platform `maproom`, kind `analysis`, group `isw`, unaligned, weight 4, no keyword filter) linked to the map page and go through normal extraction; positions come from looking up the place names, never from the image. Order (`priority`): Yemen, then Middle East and the whole-war Ukraine map, then others, then Ukraine's sections. Maps over `MAX_SPAN_DAYS` (weekly, monthly), month-only themes, and maps older than `MAX_AGE` (36 h) are not read. Tested 2026-10-03: all findings from the Taiz/Lahij and Sumy maps matched the images.
- `pipeline/recency.py`: drops old stories that arrive with a fresh date. News-only events, attack waves included (not alert groups), are searched for current coverage and coverage 2+ weeks older; with no older on-topic coverage they stay; otherwise current headlines that repeat an older one are set aside as republished copies and the model compares (searches use the article's own headline when the report kept it, else the summary: the model's paraphrase found other stories), dropping only when it names the matching older headline. New claims about an old incident count as old; another incident of the same kind does not. The coverage found is recorded (`coverage`); a notable (severity 2+), not corroborated event resting on one source, with 2+ older headlines on its topic (`HOLD_MIN_OLDER`; one is thin evidence for recurring stories) and either no current coverage from another outlet or at most one current headline with an article whose own date the date check gave up on (`UNDATED_TRIES`; until 2026-10-06 an unreadable date flagged stories with 11 to 17 current headlines, half of the 88 flagged), is flagged `possibly_old` in the published copy (`held`): still on the map, but faded, not animated, never "new", with a "Possibly an old story" note, and no Telegram alert, until a second independent source joins (not hidden: the search can miss current coverage worded differently or of thinly covered places): recurring headlines ("Houthis launched ballistic missiles at Israel") relisted months later get past the model, since another attack of the same kind counts as new. At most one model call per run and at most every 30 minutes unless 8+ events wait. Bump `CHECK_VERSION` when changing the rule (drops from versions below `KEEP_DROPS_FROM` are put back and everything is re-checked).
- `pipeline/datecheck.py`: article date check, no model calls. For every recent (3 days) event built only from news reports, whatever its severity, and for items from military or government sites (`OFFICIAL`: they post photos and releases long after the fact), the article behind its first report (`_first_news`) is dated once (twice if nothing was found): `PER_RUN` (30) a run, `WORKERS` (4) at a time, this run's new events first (so an old story is caught before it shows), then the most serious, none started after `BUDGET_SECONDS` (45; requests time out after `TIMEOUT`, 10 s). The Google News redirect is resolved to the publisher (decoded from older ids, else Google's batchexecute endpoint); the date is (1) the page's own (published_time meta tags, then JSON-LD datePublished; for photos the earlier "Date Taken" / dateCreated), (2) the date in the article's address (`url_date`: "/2025/03/14/", "20250314", RTE's "/2026/1006/", a month alone read as its last day, not exact), the earlier of the two (on 2026-10-06 a third of pages refused automated reading: Reuters, NYT, Al Arabiya), or (3) with neither, the earliest Google News listing of the same headline (`first_listed`: a search for the exact headline the report kept, `title`, results with `SAME_TITLE` 0.8 of its words; `TITLE_SEARCHES` 8 a run). Held carrier positions from articles taken down by a correction are forgotten (`fleet.drop_held`). More than `OLD_DAYS` (14) before the feed's date: dropped (into `state["dropped_as_old"]`, reason logged with how it was dated); earlier than the event by more than `SLACK` (6 h), exact dates only: the event moves to it; nothing found: no change. News reports keep their item's headline (`title`, geo.py; internal, never published: `merge.public_event` keeps only the listed report fields). Each run logs how many articles it could date.
- `pipeline/analyst.py`: the regional analyst (2026-10-04, the owner's request; replaced `brief.py`, the "What changed in the last 6 hours" bullets): "What's changing, by region" at the top of the list (published as `analysis` in events.json; `briefHtml` in app.js). Each listed theater with events in the last `ANALYSIS_DAYS` (3), or flight movements, is shown to the model (`regions`): up to `MAX_EVENTS_PER_REGION` events, those of the last `WINDOW_HOURS` (6) marked new; activity counts by kind for the last 6 and 24 hours against the daily average of the 3 days before; deployed US carriers and the flight agent's aircraft in the air by role within `REACH_KM` of the theater's camera point; and up to `MAX_FLIGHTS_PER_REGION` (15) flight movements whose bases lie within reach (`flight_movements`, most notable role first, then newest), which the model may cite like events: they count as `tracked` in the tally and weigh like corroborated events for confidence (they show where aircraft went, not why; the prompt forbids inferring a mission, and a destination only where a landing was seen); published judgments carry them as `flights` (label, adsb.lol link, sentence), shown as dashed chips, with the adsb.lol credit (`flight_credit`). Up to `PER_REGION` (2) judgments per region (headline as actor-direction-what-where, trend in `TRENDS`, a sentence, cited ids), checked in `validate`: at least `MIN_CITED` (2) cited events or tracked flights, all of that region, except that one tracked flight of a notable kind (`SINGLE_FLIGHT_ROLES`: bomber, tanker, surveillance, command, government; not transports) may stand alone (the owner's example: "KC-135 departing x and headed to y"); confidence from the cited events, never the model (`tally`, `confidence`: higher with `CORROBORATED_HIGH` corroborated, moderate with one, low with none); any single-source or claimed event cited means the words must attribute or hedge (`_HEDGE`), else dropped (the first trial stated a single-source capture as fact beside a corroborated summit); cited ids stripped from the text. Written at most every `MIN_INTERVAL` (1 h) when the last 6 hours of events changed (`fingerprint`), by the first in `ORDER` (setting `analysis_order`) that gives a valid answer: the free outside providers (`providers.py`), then Gemini's regular Flash (`ask_json(model=...)`, max_tokens 8000: thinking tokens cut a 3,000 reply short), then Gemini's usual model; Gemini calls are purpose `analysis`, share `analysis_daily_max` 24, skipped below `brief_min_calls`. `by` names the model. On failure the last analysis stays.
- `pipeline/providers.py`: free outside AI providers beside Gemini, each OpenAI-compatible with its own key secret and its own daily count (`state["providers"]`, `daily_max`), never Gemini's: Cerebras (gpt-oss-120b, free 30K tokens/minute and 1M/day; `CEREBRAS_API_KEY`) and OpenRouter (free ":free" models, 50 requests a day; `OPENROUTER_API_KEY`), checked 2026-10-04; a provider without its key is skipped; models tried in order on 404/429/5xx, JSON mode dropped if refused. Not used: Groq (free tier 8K tokens/minute, under one analysis request), GitHub Models (every request from this repository's Actions got a bare "OK"). Offloading (2026-10-04, the owner asked to move calls off Gemini): text-only `extract.ask_json` calls whose purpose has a route (`provider_routes` in sources.yaml, else `providers.ROUTES`: recency, frontline, frontline_isw, frontline_review, frontline_social; `SELF_ROUTED` analysis picks its own via `analysis_order`; images (maproom), dedupe, fleet, split stay on Gemini) go to the routed providers first (`ask_routed`) within the purpose's daily token share there, and to Gemini only when none answers; extraction spills over (`extract._overflow`, `overflow_batches_per_run` 2, waiting up to `OVERFLOW_WAIT` for the minute's limit) only when Gemini can't take batches (no key, out of calls, refused for billing, rate-limited, busy with no other model, no model answering; `_gemini` returns why). Provider caps: `daily_tokens` (Cerebras 900K of 1M), `tokens_per_minute` (27K of 30K; `_pace` waits up to `MAX_WAIT` 25 s within the run, else Gemini), `daily_max` requests (Cerebras 1000); a 429 cools the provider for `COOL_DOWN` (60 s), or for the day if it names the daily limit (`full`). Cerebras counts the answer allowance (max_tokens) against its minute, so a full analysis (about 24K tokens plus 8K) was refused even alone: for a provider with `tokens_per_minute` the analyst trims each region to its first events (new, then most serious) until the request fits (`_fit`, down to `FIT_MIN_EVENTS` 12; 24 a region on 2026-10-04) and may wait `ANALYSIS_WAIT` (65 s) for a clear minute. Overflow extraction asks gpt-oss for `reasoning_effort: low` (`effort`) with max_tokens 3,000 above `max_output_tokens`: at the default it thought through all 9,000 and the answer was cut off. Trial 2026-10-04: a 40-post batch read in 3 s (18 records), the analysis written by Cerebras (12 judgments), front-line claims and review on Cerebras. Tokens come from the reply's `usage`, else estimated; tallied per provider and purpose (`state["providers"][name]`: count, tokens, by) and for Gemini (`state["llm_calls"]["tokens"]`), logged each run as two `[budget]` lines, to decide later whether dedupe can move. Callers gate on `extract.room(purpose)` (the larger of Gemini's paced share and the providers' room), not `share_left`, so a used Gemini share doesn't stop a routed job.
- `pipeline/alerts.py`, `pipeline/config/alerts.yaml`: Telegram alerts (Bot API sendMessage, plain text). Dedupe by (event id, rule) in `state["alerts"]`; first run records everything as seen and sends only "Alerts are on"; at most `max_messages_per_run` messages, else one digest; the bot token must never be logged.
- `pipeline/archive.py`: permanent history on the data branch, `archive/<day>.json` (published events by UTC day of `time`) and `archive/fleet/<day>.json`. Day files are merged, not rebuilt (events aged out of the working set stay; taken-down ids are removed) and written only when their contents change. Keep archive files forever.
- `pipeline/hunter.py`: corroboration hunter. Up to 8 severity-2/3 single-source or one-sided events from the last 12 h get a Google News search (place + type keywords, last day), at most twice per event and 3 h apart (`state["hunter"]`). Results enter the extraction queue at weight 4, credited per outlet like other Google News results (listed outlets count on their own; unlisted ones share the `google-news` group). It must make no model calls.
- `pipeline/corrections.py`, `pipeline/config/corrections.yaml`: hand corrections by event id, each with a required `note`: `hide`, `edit` (summary, place, lat, lon, type, severity), `drop_report` (by URL). Hides and edits are applied to the published copy (reversible, labeled "Corrected"); dropped reports are removed before scoring; reports of hidden events and dropped URLs are filtered out of candidates so nothing is re-created. Event ids are shown at the bottom of the detail view.
- `pipeline/merge.py`: merging reports into events, attack waves, drone and missile alert groups, confidence rules. Arms transfers and own-force moves (`_find_transfer`) join only with the same supplier, recipient and kind, within `TRANSFER_WINDOW` (72 h) of when the event began (it was measured from the latest report, so one event kept growing), and on the same route (`_same_route`: both ends within `ROUTE_KM` 250 where both name them; a country moving its own forces must name the same ends, or with no ends be pinned in the same place): until 2026-10-04 "US forces moved" matched every US move anywhere, and one event dated 29 September had absorbed 23 reports, the Iraq withdrawal through B-1 bombers leaving RAF Fairford on 4 October, which never showed. `split_overgrown_transfers` (once per `TRANSFER_SPLIT_VERSION`) kept each overgrown transfer's first report and sent the rest back to the model as items (their summaries, credited to their original sources, `max_age_h` 30 days). Diplomacy and legal steps (`TALKS`) match by parties (`_same_talks`: two in common; the same parties with some shared wording; or one list within the other, [PK] and [PK, SA, YE], with closer wording, `TALKS_SUBSET_OVERLAP`) across theaters and across the two types; interchangeable spellings count as one word (`_SPELLINGS`: Makkah, Mecca), and beyond the 400 km radius when the parties are the same and the wording close (`_same_statement`). Deployment reports with the same acting country, the same country concerned, and similar wording (`_same_buildup`) merge however far apart their pins are. In `LOOSE_FAMILIES` (deployment, hybrid, naval, incursion), a report pinned to a whole country, region, or sea (`_broad`) joins a same-country (any country for a sea) report with similar wording (`_same_story`, place words ignored), and two broad pins need similar wording even when close. Attack waves group by attacker and target country, or for launches into the sea the same named sea whatever country the reports give (`_same_target`, `geo.sea_exact`: "Sea of Japan" with JP and "East Sea" with KR are one North Korean launch), within `WINDOW` of the wave's start (no fixed day boundary); unattributed strikes on a wave's places join it. A launch report pinned to the attacker's own territory and naming it after "fired/launched from" ("North Korea fired a ballistic missile from Wonsan", not denials; `merge.launch_sites`, `_launch_report`) is folded into the attacker's wave within `WINDOW` as a named launch area (`origins`), so the line is drawn from there; the prompt also asks for the launch site in origins and the place where the missiles went. A new event's id is the hash of its first report's link; a second event from the same article (a roundup) gets the link plus its summary (`_new_id`), and stored events sharing an id are given their own at load (`unique_ids`; the one with most reports keeps it). `consolidate` folds stored events the rules now join (the earliest id stays; folded ids are removed from the archive); stored strikes and ground fighting fold only with the same place and closely matching wording (`STRIKE_FOLD_OVERLAP`), since broad pins like "Gaza" hold many separate strikes; a strike or fighting report pinned to a whole country joins a same-country event with that close wording and the same names (`_same_broad_hit`, `_names`). Every wording match needs at least `MIN_SHARED` (2) words in common: one shared word once pinned a carrier mishap to Istanbul. For naval events, a report citing UKMTO or JMIC (`MARITIME_AUTHORITY`) leads the headline. Stored diplomacy and legal steps fold with the same parties and closely matching wording (`TALKS_FOLD_OVERLAP`); looser pairs are left to the same-story check.

## Rules that must not be broken

- **Honesty over drama.** Summaries are written by the model in its own words; only summaries and links are published, never full post text. Never add or imply attribution a source doesn't make (a UKMTO "unknown projectile" stays unknown until someone attributes it). The legal layer records stated legal bases; it never assesses them.
- **Confidence rules** (`merge.apply_status`): corroborated = 2+ independent source groups with at least one unaligned (or opposing sides agree); unconfirmed = one unaligned source; claimed = only sources aligned with one side. Sources with the same `side` never corroborate each other. Weak groups (`WEAK_GROUPS`: `google-news`, `bluesky-search`) count only when no other group reported the event, and together count once. GDELT (3+ outlets nearby) counts as one unaligned source. Google News results count per outlet for outlets listed under `outlets:` in `sources.yaml` (tier 1 = reputable, weight 3; state or partisan media carry a `side`; outlets with one owner or newsroom share a `group`; `names` are other names Google News shows, matched when the link doesn't give the domain (`rss.outlet_named`), and stored reports under a newly listed outlet's name are credited to it every run (`rss.relabel_by_name`); aggregators that republish others, like Yahoo, stay unlisted); unlisted outlets share the `google-news` group, which only counts when no listed outlet has reported the event (syndicated copy must not corroborate its original). Google News reports stored before outlets were told apart carry only the search's name; `rss.relabel` credits them to their outlet by article link (one 7-day re-read of the searches, then from each run's results).
- **Time.** Events are timed by when they happened (`time`, from the model's `happened` field, else the post time). `updated` is only the latest report. The merge window is measured from `time` and must never slide forward with later reports (that bug made old events reappear as new). The front end uses `time` for the window, sorting, and "new". No time may be later than the moment the post was read (`common.make_item` clamps it; `run.py` repairs stored events), because some feeds give date-only stamps set to a UTC midnight that hasn't happened yet.
- **Positions are never estimated.** Carriers show their last reported position with its date; aircraft their last transponder position with its time (never extrapolated); supply routes only use named endpoints (country-level routes, and routes to a US command's region, are drawn faint); an event placed at a US combatant command (CENTCOM and the others) goes to that command's region, labeled and approximate, never its headquarters (`geo.COMMANDS`, `geo.pin_commands`), and a deployment that says it comes "from" a command becomes a movement (`arms_transfer`, supplier = recipient) out of that region to its place, while a country's own ships or aircraft on a port call, visit or exercise abroad are a deployment at the destination, not a route (`merge.own_force_visits`, `VISIT_RE`; Russian warships "arrived in Indonesia for a business visit" were drawn from Vladivostok), and a country's purchases, contracts, approvals or production with its own industry (own forces, not both endpoints named) are arms production, type `production` (`merge.own_procurement`, `PROCURE_RE`), while a purchase or sales deal between two countries with nothing delivered is diplomacy (prompt only); supply routes (and "active") follow the time window, not a fixed 30 days; launch lines from assumed launch areas (`ANCHORS` in app.js, by attacker: RU, UA, IR, YE, LB, IL, KP; Yemen's are Houthi-held: Sanaa, Hodeidah, Saada) are drawn faint, only for drone and missile events (a wave corrected to another type gets none); a launch site that is only the attacker's country ("launched from Yemen", `wholeCountry`) is not a site: the country's middle fell in the government-held Hadramawt desert, so Houthi launches at Saudi Arabia were drawn from there (2026-10-05); such origins are skipped and the assumed launch areas used.
- **Map language.** Territorial control is a muted sand fill under the markers: a source's published shapes, with its date, and contested or infiltrated ground hatched rather than given to a side. The only estimate is a shape traced from a source's own map picture where it publishes no data (Yemen, the owner's request), always marked approximate (dashed edge, hover and legend note) and linked to that map. Front-line areas are the site's own assessment, never a source's shapes: one broad shape per side in each conflict, drawn with a flowing dashed edge, with no lone circles or specks: only corroborated control is shaded, so one side's word is never shown as control, and a capture the agents confirmed always shows. The one exception is the one-time Wikipedia fill-in (`frontline/wikipedia.py`, the owner's request): its towns, not its shapes, shade only where the agents have nothing, credited with each map's date and licence in the Sources list at the bottom.
